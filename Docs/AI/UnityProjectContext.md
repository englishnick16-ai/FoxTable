# Контекст проекта FoxTable

Новый проект, создан 11 ноября 2026. Локального Unity Editor и Unity MCP нет. Используется Unity Build Automation: проект и настройки описаны в `Docs/CLOUD_BUILD.md`. Сборка №4 создала ARM64/IL2CPP APK; интерактивный Editor и устройство не подключены. Пакеты стороннего MCP не устанавливались.

## Среда и архитектура

- Базовая версия: Unity 6000.0.62f1; Built-in Render Pipeline, без URP/HDRP.
- Цель: Android 8+ (API 26), ARM64/IL2CPP. Ориентация автоматическая, безопасная область экрана учитывается процентными отступами.
- Шрифт: DejaVu Sans с кириллицей, лицензия в `Docs/DejaVu-LICENSE.txt`.
- UI: UI Toolkit, C#-создание дерева, `Resources/FoxTheme.tss` импортирует стандартную тему, собственные стили в `FoxTable.uss`.
- Ввод: стандартные PointerEvent UI Toolkit; отдельный Input System не используется. Pinch и drag обрабатываются в `BattleBoard`.
- Сеть: UnityWebRequest + JSON, серверный авторитет; нет NGO/Mirror/Photon/Relay.
- Сервер: Python 3.10+, SQLite WAL, один процесс и RLock вокруг изменяющих операций, REST/HTTP-опрос.
- Сцена генерируется редакторным меню через Unity API; YAML сцены вручную не создан. Точка входа — RuntimeInitializeOnLoadMethod в FoxTableApp.
- Runtime-код в `Assets/FoxTable/Runtime`; Editor-код в `Assets/FoxTable/Editor`; asmdef пока нет, используются Assembly-CSharp и редакторная сборка.

## Владение

- RoomClient: сохранённая сессия, очередь команд, повтор с requestId, опрос и загрузка карт.
- FoxTableApp: UI, навигация, Android picker callback, применение снимков к представлению.
- BattleBoard: проекция сцены, жесты, локальное предварительное перемещение, сетка/туман/шаблоны.
- FoxTablePanels: дополнительные мобильные панели действий, освещения, профиля и предпросмотра.
- Server/visibility.py: пересечение отрезков, обзор клеток, свет и аддитивная миграция v1 → v2.
- Models: сериализуемые DTO и минимальный JSON-encoder для операций с отсутствующими необязательными полями.
- Server/server.py: единственный владелец боевого состояния, прав и результатов кубиков.
- FoxTableBuild: подготовка сцены/настроек и сборки Android.
- FoxGallery.java: Android ACTION_OPEN_DOCUMENT, callback с base64 без общих разрешений на хранилище.

## Правила продолжения

Сначала импорт/Console в Unity, затем два клиента и Android. Сохранять серверный авторитет; не доверять клиентским результатам кубиков или общей замене снимка. Не менять GUID после импорта. Не устанавливать Unity MCP автоматически. Не выдавать fog-оверлей за криптографическое сокрытие фонового изображения. Не хранить реальные ключи или SQLite-базы в исходном архиве.

## Обновление 0.2

Снимки v2 включают barriers, currentCells/exploredCells, профили зрения/света, слои, временные HP и действия жетонов. На сервере хранится exploredBy, который никогда не передаётся клиентам. GM получает пустые currentCells/exploredCells (обязательные массивы для JsonUtility); игрок получает вычисленные. Схема SQLite прежняя, новые поля живут в JSON. Перед миграцией сохранить backup.

Предпросмотр POST /api/rooms/{code}/preview доступен только GM и не записывает историю. RoomClient запрещает действия в режиме предпросмотра и не переключает вид при незавершённой очереди. Сообщения combat содержат refs и фильтруются по видимым жетонам; базовое изображение карты всё ещё передаётся целиком.

## Обновление 0.3: локальная кампания

RoomClient.IsLocal переключает очередь действий на LocalGame.ApplyCopy; онлайн POST/GET не менялись. LocalGame применяет команды к копии RoomState и увеличивает revision только после успеха. LocalCampaignStore хранит version=1/state в persistentDataPath/local/campaign.json отдельно от session.json, карты — по случайным hex ID. File.Replace создаёт атомарное обновление с .bak. Отложенная запись объединяет движения кисти; pause/quit/выход сначала применяют остаток очереди, затем сохраняют. При ошибке записи выход в меню отменяется.

FoxTableApp показывает локальную кнопку до онлайн-форм, отдельный статус и меню сохранения; повторный вход продолжает кампанию. Это мастерский стол одного устройства, без LAN/Bluetooth и player preview. LocalGameChecks запускается Prepare как блокирующая проверка перед сборкой; Editor/устройство пока не подключены интерактивно.

Сборка 0.3.0 №6 завершена успешно: commit 4f11e6167ce3888a2eee3746ab2ee47e6054f9f8, 33 локальные проверки в Unity и 49 серверных тестов прошли. APK 20 011 904 байт, package com.foxtable.mobile, versionCode 6, minSdk26/targetSdk37, ARM64. Подпись v2 присутствует, сертификат совпадает с 0.2.0. На Android не запускался; не выдавать автоматические проверки Windows Editor за проверку Android persistentDataPath/жизненного цикла/UI.

## 0.4: рабочее пространство карты

Запрос: непонятный/нестабильный UI, модели для заполнения карты и картинка с сеткой. Изменены телефонное меню, панели, выбор и расстановка. Каталог 32 оригинальных SVG/PNG (без сторонних ассетов). Поля artId/rotation у TokenState; background/gridColor/gridOpacity/mapPixelsPerCell/mapOffsetX/Y у SceneState — аддитивные, формат2 и версия локального save1 сохранены. Сервер также принимает и проверяет новые поля; игрок не получает прав их менять. Обновление сервера требуется для новых онлайн-возможностей.

BattleBoard удерживает visual elements между жестами/снимками, фиксирует исходную точку drag, откладывает Fit до появления размеров viewport; фон рассчитывается MapLayout без искажения пропорций. UI не пересоздаёт формы при каждом revision; журнал обновляет только сообщения, выбор фигуры показывает контекстную строку. Декор исключён из боевых HP-элементов. Каталог поддерживает повторные штампы, поворот/фиксацию и слои выбора. Undo — только локальные последние20 действий, не хранится между запусками.

FoxTableWorkspace содержит каталог, инструменты, предпросмотр импорта и калибровку. Импорт: PNG/JPEG → предпросмотр → число клеток или пикселей/сдвиг → подтверждение → загрузка/запись. MapImage проверяет размеры до выделения texture. Клиент хранит онлайн-доступ при обычном выходе в меню и не открывает комнату автоматически при старте.

Подтверждённые по коду механизмы старых неудобств: перестроение views в Refresh, пересоздание панелей на revision, stretch фонового изображения, Fit до первой раскладки. Конкретные симптомы телефона пока не воспроизведены на устройстве; не обещать полную стабильность и паритет. Внешний CLI макетов заблокирован auto-review из-за неподтверждённой телеметрии PostHog; обход не выполнялся. UI реализован в Unity напрямую.
